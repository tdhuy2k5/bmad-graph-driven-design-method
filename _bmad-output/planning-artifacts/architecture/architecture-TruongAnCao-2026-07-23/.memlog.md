- decision: paradigm is "Layered Static-First with BaaS Islands" — static shell (SSG) for SEO routes, BaaS listeners as isolated real-time islands (comments), client-only cart island, and a gated admin SPA route. Prevents mixing rendering modes ad hoc per developer.
- decision: AD-1 — Rendering strategy is route-scoped and immutable: product listing + PDPs use SSG + `revalidateTag` ISR; comments use Firestore real-time client listener (never SSR/ISR); admin uses client-only dynamic import (no static generation); checkout handoff is a pure client-side URL compose. Prevents a builder slipping PDP onto SSR (breaks SEO) or admin onto SSG (breaks auth guard).
- decision: AD-2 — Firestore data boundary: `products` collection is the single source of truth for catalog; `comments/{productId}/entries` sub-collection is write-once by authenticated users (Google/GitHub), read-only to the storefront. Admin writes to `products`; no other writer. Prevents two paths owning product price.
- decision: AD-3 — ISR cache invalidation: Admin product save calls a Next.js Route Handler (Server Action) that calls `revalidateTag('product-{id}')` and `revalidateTag('product-list')`; Vercel revalidates on next request. `revalidateTag` preferred over `revalidatePath` because one product edit fans out to both PDP and listing. Prevents a builder using time-based ISR only (stale prices) or using `revalidatePath` across two routes.
- decision: AD-4 — Auth gate shapes: public storefront = unauthenticated; comment posting = Firebase Auth (Google/GitHub, enforced by Firestore security rules); admin route (`/admin`) = Firebase Auth + server-side email whitelist check in a Next.js middleware (`matcher: ['/admin/:path*']`). Two distinct shapes — middleware + rules — must not be conflated. Prevents admin gate being only client-side.
- decision: AD-5 — Cart state lives exclusively in `localStorage` (client-only); no server state, no cookies, no Firestore persistence. SSR hydration mismatch avoided by lazy-mounting the cart UI after `useEffect`. Quota-exceeded errors from Firestore comments must not affect cart or checkout flow — caught at the BaaS layer boundary only. Prevents a builder syncing cart to Firestore (BaaS write costs, free tier risk).
- decision: AD-6 — Zalo handoff format: cart compiled into a single UTF-8 text string (product name × qty × price, Vietnamese labels), URL-encoded via `encodeURIComponent`, appended to Zalo OA deep link (`https://zalo.me/OA_ID?text=...`). Hard cap: compiled message must not exceed 1,500 chars (safety margin under the 2,000-char API limit). Messenger fallback link (`https://m.me/PAGE_ID?text=...`) rendered in parallel. Prevents truncated Zalo messages.
